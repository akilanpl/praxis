# Runtime and trust boundaries

React/Vite calls the loopback Python HTTP control plane. Authentication uses salted PBKDF2 passwords and hashed, expiring bearer sessions. Every private record access checks the current owner. SQLite WAL stores registry revisions, suites, worlds, runs, assertion/evidence JSON, artifacts, pairings, votes and audit actions. A two-worker executor invokes user-controlled providers. It persists each structured event and the final result. Hash-addressed uploaded bytes are stored beside SQLite; HTML remains text.

Python adapters implement OpenAI-compatible, Ollama and custom HTTP inference, a bounded agent tool loop, and bounded conventional application HTTP contracts. Each suite has immutable versioned public fixtures, independently evaluated schema/DSL assertions, per-task attempts/errors/timing, unknown cost and explicit provenance. Cancellation is observed between calls; network requests have deadlines. Interrupted process runs are marked interrupted at startup. Resume of individual tasks is unsupported.

The separate TypeScript Cloudflare Worker validates Supabase Auth tokens and forwards those JWTs to PostgREST; RLS remains the authorization boundary. It supports only metadata/evidence routes and never inference, arbitrary URL proxying or workload execution. The local app is not wired to Supabase login; replacing the local API URL alone does not produce a full cloud product. See cloud.md for setup prerequisites and dry-run results.

World replay is a deterministic state machine with a reference demo policy. Growth measures actual entity completion before adding entities/dependencies/perturbations. It is distinct from the external-model-driven tool-agent suite. A replay hash covers the full immutable spec and transitions; latest replay is persisted with its world.

Arena pairs only different targets with exact conditions (suite digest, seed, target kind, max tokens, temperature, timeout), task, MIME and trust. Assignment is randomized once and retained. The match selection lock prevents concurrent pair duplication in this single-process local runtime. A database primary key prevents duplicate account/match votes. Elo updates are recomputed chronologically and scoped by conditions/trust, never blended into a universal score. Both-bad votes are recorded without relative rating updates. Official objective rankings have no data because no trusted operator runner pipeline exists.

## Release additions — 2026-11-10

`apps/website` is an independent static React/Vite entry point. It reads public suite definitions at build time and links to repository evidence; it has no dependency on local authentication or the metadata Worker. Root build emits both frontends. Website hosting can be static, but no deployment is performed.

Suite inspection is version-qualified (`slug@version`), and ambiguous unqualified revisions are rejected. Execution records include safe configuration, aggregate usage, named unexecuted tasks and full category denominators. Task output hashes are recalculated after known-credential redaction; the final digest covers the redacted evidence. The run result and its generated artifact rows share one SQLite transaction. Restart/idempotency queries operate beyond the UI list cap. Agent adapter errors retain prior tool/state traces; traces are still persisted at task completion rather than durably streamed per step.

## Reviewed reliability boundaries

The frontend now has a small session-aware API transport; the React/Vite architecture and independent website are preserved. Internal suite/history/rating and active-run queries are independent of capped list presentation. Model/application parsing rejects malformed HTTP and unsafe/non-finite JSON. Mutation retries are disabled for POST; step-exhausted agents cannot pass. Known-secret redaction happens before grading and does not corrupt protocol metadata.

New private object writes use fsynced temporary files, atomic replacement and directory sync. SQLite/object snapshot and new-directory restore tooling verifies manifests/hashes/schema; newer schema versions are refused. Account password format is versioned with legacy on-login upgrade. These are local reliability boundaries, not distributed service or arbitrary-code isolation.

Acceptance scripts bind receipts to the source commit, clean runtime source and file hashes. Stale/missing receipts fail acceptance. Separate V8 TypeScript reports and Python/greenlet coverage feed changed-line/security-branch checks, including the website. Actual PostgreSQL tests now cover concurrent request uniqueness, rollback and restart persistence with synthetic auth claims. See the independent review for limits and exact evidence.
