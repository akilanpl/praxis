## Security / architecture assessment

Threat actors: malicious browser origin, unauthorized local account, malformed or malicious endpoint response, untrusted upload, client-supplied metadata, interrupted process/storage; deployment operator is trusted for local endpoint configuration. Local arbitrary URL reachability is intentional for owned apps/Ollama, not a hosted SSRF service. HTTP authorization acknowledgment is not independent proof of ownership. No arbitrary executable workload is supported.

Reviewed outcomes: salted PBKDF2 + hashed expiring bearer sessions; exact owner checks on targets/runs/worlds; logout revocation; loopback bind + origin/host gates; no ambient cookie authority; parameterized SQLite access; POST acknowledgment + mutation consent; no redirects; response byte/read limits; inert HTML/text; public Arena consent and self-vote exclusion; immutable append-only cloud metadata with forwarded user JWT/RLS; trusted flags not taken from clients. Evidence hashes are integrity checks, not operator attestations. CSP, errors and metadata avoid direct credential disclosure. Remaining defects above and limited local rate controls preclude public API hosting.

Assessment references (guidance, NOT certification): OWASP ASVS project, https://owasp.org/www-project-application-security-verification-standard/ ; OWASP Session Management Cheat Sheet, https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html ; OWASP SSRF Prevention Cheat Sheet, https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html . Session and SSRF reference pages retrieved in cloud; apply separate local/cloud threat models rather than blanket private-address rejection that would break local inference.

Architecture remains appropriate for a private local evaluation workspace and a separate static site. The one-file UI is difficult to review/cover; formatting and a small session-aware transport module are justified, a framework rewrite is not. The metadata Worker remains optional and cannot be presented as hosted evaluation parity.

### Additional findings from deeper acceptance

- **R12, P2, inherited `server.py` account hashing (original lines 96–100):** PBKDF2-HMAC-SHA-256 used 240,000 rounds without a version marker. OWASP Password Storage guidance retrieved during review recommends at least 600,000 for that algorithm. No password compromise was observed. New hashes now carry an explicit 600,000-round prefix; successful legacy logins atomically upgrade hash/salt, failed logins do not rewrite hashes, and unsupported formats fail closed. Existing accounts remain usable; rollback to old code requires the pre-upgrade snapshot. Regression: `tests/test_password_upgrade.py`. Reference: https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html .
- **R13, P2, inherited `apps/web/src/style.css` / report timeline render:** the stricter production browser test failed at 390 px. Actual compact event JSON expanded document scroll width to 864 px despite a 390 px viewport. `report-layout-red.json/png`, `mobile-failed-browser.log` and the failed gate receipt retain reproduction. Repair wraps event text without hiding it and gives assertion tables named, keyboard-focusable scroll regions with readable column widths. Critical reports are now tested at 390/768/1280; final exact-source gate must pass these checks.

Redaction tests additionally cover credentials colliding with status/trust labels and hash characters: protocol enums/digests remain structurally valid while untrusted reflected payloads are sanitized before grading. Inbound body reading now uses an elapsed deadline and bounded buffer, not just an idle socket timeout. These decisions remain private local-service defenses, not public-server denial-of-service certification.

R9 also rejects JSON exponent overflow (`1e309`), non-finite usage, invalid Unicode and nesting beyond 64 levels before grading/persistence.
