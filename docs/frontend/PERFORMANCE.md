# Frontend performance scope

Baseline `75243f7`: production initial JS 247,546 bytes (Vite gzip report 79.22 kB), CSS 5,469 bytes (Vite gzip report 1.81 kB). Baseline test/build evidence is retained from the original release gate and re-run frontend baseline.

The redesign introduces no runtime dependencies or remote fonts. React lazy-loading separates run inspection/report export, suite editing/exploration, artifact inspection and settings. The shell and overview remain in the initial route. `scripts/frontend_bundle.py` measures actual artifacts and checks initial JS <=300,000 bytes, its gzip estimate <=100,000 bytes, CSS gzip estimate <=12,000 bytes, and at least four lazy chunks. Final measured values are recorded alongside acceptance evidence; gzip estimates are not loopback wire-byte measurements. The current local API serves uncompressed no-store assets; its headers were not changed to inflate a performance result.

List results populate cached target/suite/history collections instead of issuing duplicate list fetches. Bulk history is not fetched in the background on every settings/run-detail route. Completed runs stop polling. Registry filtering/sorting/pagination renders only 12 rows at once; only the selected artifact media is mounted. Nested text search walks loaded JSON without creating a second whole serialized payload. Immutable icon geometry is constructed once. Code previews initially render at most 14,000 characters with an explicit complete-output control; exports preserve the original data.

Browser evidence records real navigation/resource entries, not invented Lighthouse/TTI scores. Acceptance navigation is paced between pages to respect the unchanged real API quota; it does not mock or delay HTTP responses. These local test timings are hardware/cache dependent, not capacity or hosted performance certification. Very large API records/histories still transfer full payloads (up to the existing returned-record cap); proper server pagination/indexing would be a separate backend contract change. High-volume timelines and complete-output expansion can still create substantial DOM content. No virtualization framework or speculative backend refactor was added.
