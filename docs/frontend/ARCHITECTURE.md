# Frontend architecture

`main.tsx` remains the route/controller boundary. It uses the unchanged `api.ts` session-bound transport, stale-path/token guards, idempotency ticket and original local endpoints. Backend files, contracts, SQLite and the independent website are unchanged. Frontend `/targets` and `/reports` are projections of existing owner-scoped `/targets` and `/runs` responses, not new backend services.

`ui.tsx` supplies the shell, inline SVG icon set, semantic badges, bounded code previews and native modal primitive. `Overview.tsx` derives summaries only from persisted data. `RunInspector.tsx`, `SuiteViews.tsx`, `ArtifactInspector.tsx` and `Settings.tsx` are lazy route chunks. No component/editor framework, new runtime package or remote font was introduced.

The shell groups primary workspace routes and reference tools, persists theme/sidebar preferences, exposes session/account navigation, and supports Ctrl/Cmd-K and keyboard drawer/dialog interaction. Search indexes only currently loaded authorized records; it cannot reveal blind-assignment identities. The browser never inspects process secrets or pretends to perform CLI backup/restore.

Session changes synchronously mask old data before effects fetch the next owner scope. Cached target/suite/history collections are cleared; settings and editor instances are keyed to the session. Auth payloads are not rendered in operation output. Async JSON export checks the current route/session after awaiting transport and code loading. Preferences contain no credentials. Server authorization remains authoritative.

List data is reused for registry/global navigation to avoid duplicate requests. Full history is fetched for overview/target activity or explicit run-list/comparison/report routes, not in the background on every settings/evidence route. Completed run details stop polling. Filtering, sorting and 12-row pagination operate on the API's returned records (currently at most 500); this is not server-side pagination. Very large stored histories can still produce large API payloads, which is a backend contract limitation, not hidden by the UI.

Task navigation retains every assertion table by default. Failure-only filtering is explicit; unexecuted scenarios remain above the task list and in denominators. Raw code previews cap initial DOM text at 14,000 characters with an explicit complete-output control; JSON/standalone HTML exports preserve all evidence. Only the selected artifact's media is mounted. No uploaded HTML/JavaScript executes on the workspace origin. Standalone HTML reports escape user values and deny scripts, network resources and forms with their own CSP.

Suite editing constructs an explicit new immutable version. Structured metadata, schema/assertion fields and full JSON share the same definition. Frontend feedback checks basic shape; the local API still owns schema/DSL validation. JSON fixtures remain visibly deterministic references. Target connection status is shown only after an explicit diagnostic response; declared capabilities are not certified capabilities. HTTP targets retain ownership/mutation acknowledgements and are clearly actual HTTP execution.

Actual API/browser acceptance is in `scripts/frontend_acceptance.py`; it owns a private disposable SQLite workspace and owned HTTP server. It exercises first-time/filled views, authoring/revision, all evaluation kinds, failure and cancellation, inert upload, comparisons/votes, exports, expiration, palette/drawers, six widths and axe sampling. Private databases/tokens are excluded from uploaded/committed evidence. Navigation pacing respects the real API quota; responses and data are not mocked. Existing backend, Worker, browser/lifecycle, website and full-gate checks remain enabled. The pre-existing Windows qualification failure is an unsupported platform limitation, not relabeled as frontend success.
