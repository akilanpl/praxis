# Threat model and limits

The supported local deployment is a single user's computer and loopback-only HTTP service. It is not a public multi-tenant hosting system. Do not port-forward it. Host allowlists resist DNS rebinding; browser origins are exact allowlisted; no cookie authority is used; bearer authorization plus JSON-only mutations avoids ambient-authority CSRF. Secrets are never accepted in target registry fields and URL userinfo/query/fragment are forbidden. Provider redirects are denied. Model credentials are process environment values, not client inputs. Untrusted endpoint responses are size bounded; outputs render as escaped text. CSP denies frames, objects, external scripts and off-origin connections.

Uploads inspect signatures and a bounded amount of media metadata. They are not malware scans or perceptual quality certification. Only source-controlled owned website fixtures can execute in the current browser harness. A blank browser context with blocked network is useful containment but not an OS security sandbox. Arbitrary untrusted code and HTML execution are refused. A separately provisioned hardened executor is required to support these workloads safely.

SQLite belongs to the host user. Local user/record isolation is tested; organizations and collaborative project roles are not implemented in the local app. The schema and its tracked migration were applied to disposable real PostgreSQL 17 in Codex Cloud; ownership/trust/persistence tests passed with a local auth.uid/JWT-claim fixture. This does not establish hosted Supabase Auth acceptance. See evidence/final/postgres.json.

Provider endpoint calls originate from the explicitly user-controlled local runner. Loopback is intentionally permitted for Ollama and owned applications. Hosted Workers never fetch user endpoints. This local endpoint reachability must not be copied into public hosted infrastructure.

Auth/request and active-run limits are local process limits; they are not distributed abuse controls. Lists cap at 500. No production log collection, automatic deletion/retention, runner enrollment, adversarial bot detection or public moderation service is implemented. Back up `.praxis/` only to a location appropriate for private prompts. Logout revokes local sessions. No cloud deployment, paid provisioning, third-party key changes, public publishing or remote mutation occurred.

## Cloud release hardening — 2026-11-10

HTTP applications require `authorized:true` acknowledgement before any network request and distinct `allow_mutation:true` consent for POST. This is an operator declaration, not independently proved endpoint ownership. Local endpoint access deliberately permits loopback; it is never a hosted SSRF proxy. Models use explicit operator-configured endpoints; redirects remain rejected. Total response read deadlines supplement socket timeouts and byte limits. Provider protocol types/non-finite JSON and invalid usage are rejected. Known process-resolved provider credentials reflected in outputs/metadata are redacted before evidence hashing. Arbitrary secrets in prompts or output cannot be identified automatically; avoid including them.

Final result and generated artifact metadata commit atomically. Active-run recovery and request-key lookup inspect the database independently of list pagination. HTTP Transfer-Encoding and duplicate Content-Length are rejected. Agent error records preserve already-executed tool traces. HTML reports escape observations, expectations and configuration. The separate static project website has no login, runtime secrets, tracking or evaluation endpoint calls.

Custom suite schemas remain operator-supplied evaluation logic inside the local process; no hostile-schema resource-isolation guarantee is made. Cancellation remains cooperative and task resume is unsupported. No production authentication, public abuse-control or hardened arbitrary-code executor claim is made.
